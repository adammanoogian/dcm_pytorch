# v0.6.0 Milestone Audit — Goal-Backward Verification

**Date:** 2026-06-10
**Method:** Goal-backward audit (does the codebase deliver each phase's ROADMAP goal,
not just "did the plans execute?"). Three parallel read-only audits over phase SUMMARYs,
referenced code, cluster logs, and git history.
**Scope:** v0.6.0 (Phases 20–27) + the undocumented Variational Laplace (VL) engine.

## Headline finding

**Every plan executed (31/31 have SUMMARYs), but the milestone's headline scientific
claim — "DCM interpretability on *real* neural data" — was NOT delivered.** It was
validated on synthetic ground truth. Real-data application (Phase 22 real Cam-CAN,
Phase 24 real foundation models, Phase 26 real M/EEG) was pivoted to synthetic,
built-but-not-run, or never planned — blocked on data access (DUA), compute (A100),
or scope. This is a legitimate research outcome; the ROADMAP simply overclaims it.

The genuine, defensible deliverable of v0.6.0 is: **a validated synthetic DCM-recovery
methodology + a full SPM12-grade Variational Laplace inference engine + real
foundation-model/extractor infrastructure that is ready (but not yet run) on real data.**

## Audit verdict

**v0.6.0 is NOT "complete" as written.** It is:
- ✅ **Methodology + engine complete**: synthetic recovery validated; VL engine SPM12-grade;
  BMR validated; HVAE/SBI built; foundation extractors + parcellation real.
- ❌ **Real-data scientific claims undelivered**: Phase 22 (real Cam-CAN), Phase 24 (real
  foundation-model execution), Phase 26 (real M/EEG + SBC calibration).

Two honest closure options (decision required — see below):
1. **Scope-cut + complete**: redefine v0.6.0 acceptance to what was delivered (synthetic
   validation + VL engine + infrastructure), explicitly **defer real-data application** to a
   follow-on milestone, mark the unmet gates as deferred (not failed), and close v0.6.0.
2. **Hold open**: keep v0.6.0 open until real-data results land — long pole (DUA + A100 +
   compute), not actionable now.

Recommendation: **option 1**. The synthetic methodology + VL engine is a coherent, defensible
milestone; the real-data application is a natural next milestone (and aligns with the proposed
v0.7.0 VL-validation + real-data scope).
