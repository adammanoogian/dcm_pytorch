## What was fixed

`mar2csd` omitted SPM12's final `csd = 2*csd/ns` (`spm_mar2csd.m`), leaving the
reconstructed CSD too small by `2/ns` -- a factor of 4 on the standard fMRI grid
(`freqs[-1] = 0.25`). Fixed in `bd2448d` with `tests/test_mar_csd.py` (4 tests,
written failing first).

The fix is well-evidenced **as a forward-model correction**:

- SPM's own toolbox on a synthetic CSD: round-trip gain mean **0.9855**;
  ours before the fix: **0.2464**; after: ~1.0 (test-enforced).
- At the prior mean, the components already matched SPM exactly -- transfer
  function `S`, neuronal `Gu`, observation `Gn` all at ratio **1.000000**
  (job 55207377). Only the composite was off, and only by this scale.

## The problem: end-to-end agreement got WORSE

| | VL F | SPM F | relative_error |
|---|---|---|---|
| before fix | 577.4417 | 525.4313 | **0.0990** |
| after fix  | 399.9960 | 515.9795 | **0.2248** |

Ranking agreement stayed 1.0 in both.

## Likely confound (NOT yet verified)

The injected CSD is generated by `simulate_spectral_dcm`, which uses the same
forward that was just changed. So the fix moved the **data** as well as the
model, and the "matched problem" is not the same problem before and after. The
two rows above are therefore not directly comparable.

Suspicious detail: SPM F barely moved (525.43 -> 515.98) while VL F dropped
sharply (577.44 -> 400.00). If both data and prediction had simply scaled by 4,
a larger, more symmetric shift would be expected. That asymmetry is unexplained.

## Next step (needs the cluster; eduVPN was down when this was written)

1. **Re-run the component comparison** -- the decisive invariant. At identical
   parameters the composite predicted CSD must now match SPM at ratio
   **1.000000**, as `S`/`Gu`/`Gn` already do. If it does, the forward is right
   and the F discrepancy is elsewhere. If it does not, the fix is incomplete.
2. Check whether `simulate_spectral_dcm` should apply the MAR round-trip at
   all when GENERATING data. Applying it to both the data and the model may be
   double-counting; SPM applies it inside the generative function, not to the
   observed CSD.
3. Only after (1) and (2) settle should the 1:1 fixture-keyed SPM parity tests
   be frozen -- freezing now would bake in a number that is still moving.

## Do NOT revert without evidence

The fix makes `mar2csd` match `spm_mar2csd.m` line-for-line and is covered by a
round-trip identity test. Reverting restores a provable deviation from SPM.
Whatever explains the F change is more likely upstream (data generation) than
in this normalisation.
