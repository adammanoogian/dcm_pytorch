<objective>
Build the hardened per-cell metric layer and ground-truth guards that the Phase 30
recovery sweep depends on, WITHOUT re-deriving any fits. This plan is pure library +
tests, runs entirely on laptop, and is the dependency root for the sweep driver
(30-02) and the harvest/report step (30-03).

two known artifacts (variance-pooled R2 hiding per-region failure; `sign(0)`
mismatches on structural zeros) and the recovery design to exclude the eig_clamp
non-injective regime. Centralizing these in one module means the sweep driver and the
report consume identical, tested logic.

Output: `benchmarks/recovery_matrix_metrics.py` (assembler + guards + SNR mapping)
and `tests/test_recovery_matrix_metrics.py`.
</objective>

  <name>Task 1: Per-cell hardened metric assembler + shrinkage helper</name>
  <files>benchmarks/recovery_matrix_metrics.py</files>
  <action>
Create `benchmarks/recovery_matrix_metrics.py` with `from __future__ import
annotations`, NumPy docstrings, 3.10+ type hints, absolute imports, ruff-clean 88char.

Implement these pure functions (reuse existing helpers; do NOT reimplement math that
already exists):

1. `compute_shrinkage_ratio(std_post: torch.Tensor, std_prior: float) -> torch.Tensor`
   Returns `std_post / std_prior` element-wise (identifiability shrinkage). This is the
   "small shrinkage helper if missing" called for in the phase brief. Mirror the
   semantics of `benchmarks.bilinear_metrics.compute_shrinkage` but accept a scalar
   `std_prior` (= sqrt(prior_variance)) so it works for A (prior_variance varies per
   model) and B. Error message on non-positive `std_prior` must include expected
   (>0) vs actual.

2. `assemble_cell_metrics(cell_result: dict, *, sign_threshold: float = 0.1,
   ci_level: float = 0.95) -> dict` — turns ONE forward-model VL runner result dict
   (the `(BenchmarkConfig)->dict` output from `run_spectral_vl` / `run_task_vl` /
   `run_latent_circuit_vl`) into the hardened per-cell metric block. It must compute,
   aggregated across the per-seed lists already in the runner result:
     - `rmse_a`: median + IQR of the runner's `rmse_list` (spectral/task) or
       `a_rmse_list` (latent_circuit) via `benchmarks.metrics.compute_summary_stats`.
     - `coverage_95`: median of `coverage_list` when present (spectral/task). For
       latent_circuit, derive from the per-seed B coverage already produced upstream
       if present, else record `None` with a `"coverage_note"` explaining absence.
     - `sign_recovery_masked`: use
       `pyro_dcm.models.hybrid_vae_dcm.masked_sign_recovery(pred, true,
       magnitude_threshold=sign_threshold)` per seed on the A matrices reconstructed
       from `a_true_list` / `a_inferred_list` (reshape flat lists back to (N,N)),
       then report the median. This is the MASKED sign recovery (|true|>threshold),
       never `sign(0)`.
     - `r2_per_region`: per-region R2 (NOT variance-pooled). For latent_circuit this
       maps onto `benchmarks.latent_circuit_metrics.compute_trajectory_r_squared(
       predicted, observed, pooled=False)` — but the runner does NOT currently emit
       per-seed predicted/observed trajectories. So `assemble_cell_metrics` must read
       a per-seed `r2_per_region_list` key IF present and median-aggregate it; when
       absent (spectral/task, which have no trajectory), set `r2_per_region=None` and
       a `"r2_note"`. (The driver in 30-02 is responsible for populating
       `r2_per_region_list` for latent_circuit by calling compute_trajectory_r_squared
       with pooled=False; this assembler only consumes it.)
     - `shrinkage`: median across seeds of mean `std_post/std_prior`, using
       `compute_shrinkage_ratio`. Read per-seed posterior std from a
       `shrinkage_list` key the driver supplies (mean shrinkage per seed); when absent,
       record `None` + note. Do NOT silently fabricate.
     - `n_success`, `n_failed`, `convergence_rate` passed through from the runner dict.
   Return a flat dict suitable for JSON serialization (Python floats / None, no
   tensors). Raise `ValueError` (expected-vs-actual message) if `cell_result` has
   neither `rmse_list` nor `a_rmse_list`.

Cite the requirement IDs in the module docstring: VLREC-02 (metric hardening),
VLROBUST-03 (shrinkage/boundary characterization input). Reference the artifacts this
guards against (pooled-R2 R1, sign(0) R2 from
.planning/research/v0.7.0/PITFALLS.md / SUMMARY.md).
  </action>

<task type="auto">
  <name>Task 2: Near-boundary-A exclusion + per-model SNR injection</name>
  <files>benchmarks/recovery_matrix_metrics.py</files>
  <action>
Add two more functions to `benchmarks/recovery_matrix_metrics.py`:

1. `exclude_near_boundary_A(A: torch.Tensor, *, lo: float = -0.05, hi: float = 0.0)
   -> bool` — returns True if A is ACCEPTABLE (its max real eigenvalue is NOT in the
   exclusion band `(lo, hi]` i.e. NOT in [-0.05, 0]), False if it falls in the
   near-stability-boundary band that triggers eig_clamp non-injectivity (VLREC-03,
   pitfall N2). Compute `max(real(eigvals(A)))` via `torch.linalg.eigvals`. Document
   that a stable A must already have max Re eig < 0; this band-check additionally
   rejects A whose max Re eig sits in [-0.05, 0], keeping ground truth comfortably
   inside the stable, injective regime. Provide a companion
   `resample_A_until_accepted(make_A_fn, *, max_tries: int = 50) -> torch.Tensor`
   that calls a zero-arg `make_A_fn` (a closure over `make_stable_A_spectral` /
   `make_random_stable_A` with a per-try seed) and returns the first A passing
   `exclude_near_boundary_A`, raising `RuntimeError` with tries count (expected vs
   actual) if none pass. The 30-02 driver wires `make_A_fn` so each rejected draw uses
   a fresh seed.

2. `snr_for_model(variant: str, snr_level: float) -> dict` — maps an integer SNR level
   onto the correct simulator knob per forward model, returning a kwargs dict the
   driver splats into the simulate call:
     - `"task"` and `"latent_circuit"`: `{"SNR": float(snr_level)}` (their
       `simulate_*` functions take an `SNR` kwarg directly).
     - `"spectral"`: `simulate_spectral_dcm` has NO `SNR` kwarg; SNR is set via the
       observation-noise log-amplitude in `noise_params`. Return
       `{"noise_log_amplitude": <value>}` where higher SNR -> more-negative
       log-amplitude (less observation noise). Document the mapping formula
       (e.g. `log_amp = -log(snr_level)`) and that the driver constructs the
       `noise_params` dict from this. Cite that this is the ONE place SNR semantics
       diverge across the three models, so the matrix axis stays comparable.
   Raise `ValueError` (expected-vs-actual variant) on an unknown variant.
  </action>
