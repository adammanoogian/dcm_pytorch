Define the USER-CONFIRMED small validation grid as module constants:
  `GRID_VARIANTS = ("spectral", "task", "latent_circuit")`
  `GRID_N = (2, 4)`
  `GRID_SNR = (1.0, 3.0)`
  `GRID_SEEDS = 10`  (>=10 seeds/cell)
Note for latent_circuit: its ground truth is the fixed N=4 bilinear topology
(`_build_ground_truth`), so the N axis does not apply the same way. Handle this
explicitly: for `latent_circuit`, IGNORE the N axis (it is intrinsically N=4) and emit
ONE N-entry (record `n_regions=4` and a `"n_axis_note"`), so the grid does not
fabricate non-existent N=2 latent-circuit cells. Document this asymmetry in the module
docstring. Spectral and task use both N in {2,4}.

Provide:
1. `enumerate_cells() -> list[dict]` — the canonical ordered list of cells. Each cell
   is `{"cell_index": int, "variant": str, "n_regions": int, "snr": float}`. The
   ordering is STABLE so a SLURM array index maps deterministically to a cell. Seeds
   are NOT separate array tasks — each cell runs all `GRID_SEEDS` seeds inside one task
   (mirrors the existing per-seed runner loop via `config.n_datasets`). Compute and
   document the total task count (= number of cells). With the asymmetry: spectral 2N x
   2SNR = 4, task 2N x 2SNR = 4, latent_circuit 1 x 2SNR = 2 -> 10 cells, each running
   10 seeds = 120 fits.
2. `cell_for_index(cell_index: int) -> dict` — inverse lookup; raise IndexError
   (expected range vs actual) on out-of-range.
3. `run_one_cell(cell: dict, *, base_seed: int = 42, max_iter: int = 64,
   quick: bool = False) -> dict` — the heart of the driver:
     - Look up `RUNNER_REGISTRY[(cell["variant"], "vl")]`.
     - Build a `BenchmarkConfig` with `variant=cell["variant"], method="vl",
       n_datasets=GRID_SEEDS, n_regions=cell["n_regions"], seed=base_seed,
       max_iter=max_iter, quick=quick`.
     - Apply SNR: the existing VL runners hardcode their noise level
       (task `SNR=5.0`, latent `_SNR=10.0`, spectral uses default noise_params). The
       grid requires SNR in {1,3}. Rather than fork the runners, set the SNR via the
       mechanism `snr_for_model(cell["variant"], cell["snr"])` returns, threading it
       into the run. The CLEANEST seam: pass the snr through `BenchmarkConfig` is not
       available, so call the runner's underlying simulate with the snr knob by wrapping
       — implement `run_one_cell` to call the runner with a monkey-free approach:
       set an env var `RECOVERY_MATRIX_SNR` that a thin per-model shim reads, OR (preferred,
       no globals) replicate the runner's simulate->fit->metric loop here using the
       runner's own functions but injecting `snr_for_model(...)` into the simulate call.
       Choose the preferred path: import the same simulate/forward symbols the runners
       use and run the per-seed loop in `run_one_cell`, calling
       `exclude_near_boundary_A` + `resample_A_until_accepted` on each ground-truth A
       (spectral/task; latent uses its fixed topology and is exempt but must still log
       its max-eig-band status), and `snr_for_model` for the noise knob. For
       latent_circuit additionally compute per-seed per-region R2 via
       `compute_trajectory_r_squared(predicted, observed, pooled=False)` and collect a
       `r2_per_region_list`; collect per-seed mean shrinkage into `shrinkage_list`.
     - Pass the assembled per-seed lists through `assemble_cell_metrics(...)` (30-01)
       and return `{**cell, "metrics": <assembled>, "raw": <per-seed lists>,
       "config": {...}, "n_seeds": GRID_SEEDS}`.
   Enforce `dt >= 0.1` for task/latent (reuse the runners' `_DT_MODEL=0.1` / `_DT=0.1`
   constants; assert and fail loud with expected-vs-actual if a smaller dt is ever
   wired). Document that this driver REUSES the Phase 29 fit logic and adds only the
   SNR/boundary/metric wiring.
