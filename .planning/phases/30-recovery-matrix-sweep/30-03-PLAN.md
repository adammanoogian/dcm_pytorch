<objective>
After the M3 array job (submitted in 30-02) completes, harvest every per-cell JSON,
apply documented per-cell thresholds, and emit the recovery matrix as CSV/JSON plus a
human-readable per-cell report that labels each cell either PASS or
IDENTIFIABILITY-LIMIT-WITH-EVIDENCE — never a silent failure — and characterizes the
eig_clamp / stability-boundary regime. This is the "harvest + report" half of the
two-phase async structure; it is a POST-RESULTS step the orchestrator runs once SLURM
reports the array finished.

Purpose: VLREC-04 requires every cell to pass its documented threshold OR document its
identifiability limit with evidence; VLROBUST-03 requires the eig_clamp /
stability-boundary regime to be characterized (degradation near the boundary
documented, the non-injective regime flagged). This plan turns the raw per-cell JSON
into that verdict.

Output: `benchmarks/recovery_matrix_thresholds.py`,
`cluster/scripts/recovery_matrix_aggregate.py`, tests, and the report markdown
`.planning/phases/30-recovery-matrix-sweep/30-RECOVERY-MATRIX-REPORT.md`.
</objective>

  <name>Task 1: Documented per-cell thresholds + classifier</name>
  <files>benchmarks/recovery_matrix_thresholds.py</files>
  <action>
Create `benchmarks/recovery_matrix_thresholds.py` (`from __future__ import
annotations`, NumPy docstrings, 3.10+ hints, absolute imports, ruff 88char).

The v0.7.0 research SUMMARY notes NO principled Fisher-information per-cell threshold
exists yet; use DOCUMENTED defaults and audit outliers (this is the small-grid
prove-the-harness run, so thresholds are deliberately explicit + revisable). Define
module constants with docstrings citing their provenance:
  - `RMSE_A_THRESHOLD: float = 0.05` (research SUMMARY "RMSE < 0.05 universally; audit
    outliers" gap-4 recommendation). Document it is provisional.
  - `SIGN_RECOVERY_THRESHOLD: float = 0.80` (mirrors RECOV-05 / LC convention).
  - `COVERAGE_95_FLOOR: float = 0.85` (mirrors RECOV-06 / LC convention).
  - `SHRINKAGE_SOFT_TARGET: float = 0.7` (RECOV-07 soft target; informational, the
    Laplace-overconfidence finding means shrinkage will often be FAR below this, which
    is itself the identifiability signal — document that very-low shrinkage at high SNR
    is the expected overconfidence regime, job 55772525).

Implement `classify_cell(cell_metrics: dict, *, cell: dict) -> dict` returning:
  `{"status": "pass" | "identifiability_limit", "checks": {<metric>: {"observed":...,
  "threshold":..., "pass": bool}}, "evidence": {...}, "reason": str}`.
  - `status == "pass"` iff the cell meets RMSE_A (<= threshold), sign_recovery
    (>= threshold) and coverage_95 (>= floor) for the metrics that are present
    (skip a check with `"pass": None` + note when its metric is `None`, e.g. spectral
    has no per-region R2 / latent has no scalar coverage — do NOT auto-fail a missing
    metric).
  - Otherwise `status == "identifiability_limit"` with a `reason` string naming which
    checks failed and an `evidence` block carrying the shrinkage median, coverage,
    RMSE IQR, and convergence_rate so the limit is documented WITH EVIDENCE (VLREC-04).
  - NEVER raise on a failing cell; a failing cell is a documented limit, not an error.
    Only raise (expected-vs-actual) if `cell_metrics` is structurally malformed
    (missing the keys 30-01's `assemble_cell_metrics` is contracted to produce).
Document that this classifier implements VLREC-04's "pass OR identifiability-limit
with evidence — no silent failures" rule.
  </action>
  <verify>

RMSE_A_THRESHOLD; print(RMSE_A_THRESHOLD)"` imports clean. A hand-built passing
cell_metrics classifies `status=='pass'`; a high-RMSE one classifies
`status=='identifiability_limit'` with a non-empty `reason` and populated `evidence`.
`ruff check` + `mypy benchmarks/recovery_matrix_thresholds.py` clean.
  </verify>
  <done>
`classify_cell` returns `pass` for a good cell and `identifiability_limit` (never

  </done>
