Add `compare_free_energies()` to `validation/compare_results.py`: a relative-tolerance comparator
for the SINGLE prior-matched problem's free energy (VL `free_energy[-1]` vs SPM `DCM.F`), with the
5% relative tolerance treated as a HARD pass/fail gate per the user decision.

Purpose: VLSPM-02 requires VL F to agree with SPM F within ~5% ON THE MATCHED PROBLEM. The user has
made this a strict gate (overriding the research's softer "report descriptively" fallback). This
function encodes that gate. It is deliberately the ONLY new comparator; cross-model ranking reuses
the existing `compare_model_ranking` (relative delta-F), and element-wise `Cp` and absolute-F-across-
models are FORBIDDEN (pitfall S3). Keeping `compare_free_energies` single-problem-only is what keeps
the strict 5% defensible — it never leaks into the S3-forbidden cross-model F comparison.
