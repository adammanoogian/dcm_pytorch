# Phase 16.1 Plan 01: init_scale Sweep Diagnostic Summary

Single-seed init_scale sweep diagnostic to identify the root cause of RECOV-04 B-RMSE=0.34 acceptance failure and pick the winning init_scale for Plan 16.1-02.

Key observations:
- B-RMSE is FLAT (0.347-0.362) — init_scale has negligible effect on recovery quality.
- A-RMSE is excellent (0.088-0.097) regardless of init_scale.
- Shrinkage moves monotonically with init_scale (0.009→0.690) confirming the guide width IS being set, but B posterior MEANS remain pinned near zero.
- The problem is not initialization width — it's that 1st-order SVI with mean-field AutoNormal cannot move B posterior means away from zero given the weak multiplicative gradient signal.

## Chosen init_scale

**Chosen _BILINEAR_INIT_SCALE: NONE — escalation required.**

H1 (init_scale-too-small as root cause) is FALSIFIED. The B posterior means are stuck at zero across all init_scales. The root cause is the weak gradient signal for B parameters (B enters multiplicatively as u_j(t)·B_j·x(t), temporally sparse, and A can absorb B's average effect).

## Escalation: Variational Laplace Baseline

Plan 16.1-02 (apply chosen init_scale + re-run acceptance) is BLOCKED — its premise (a winning init_scale exists) is falsified.

**New diagnostic path:** Build an SPM-style Variational Laplace (Gauss-Newton) baseline to determine if the forward model + likelihood can recover B at all via 2nd-order MAP estimation. VL uses full-covariance Hessian updates (J'ΛJ + Σ₀⁻¹) that naturally rescale weakly-identified parameters like B by their inverse curvature, unlike 1st-order Adam in SVI.

- `src/pyro_dcm/inference/vl_dcm.py` — DCM forward-function bridge (θ_flat → BOLD)
- `src/pyro_dcm/inference/__init__.py` — Package exports
- `tests/test_variational_laplace.py` — 5 fast structural tests (PASS) + 2 slow recovery tests (cluster job 55554876 pending)
- 5/5 fast tests pass locally; ruff clean on all files

Problem is entirely in the SVI variational approximation (1st-order Adam + mean-field AutoNormal). v0.3.0 closes with VL as the recommended bilinear inference engine. SVI guide-family exploration (AutoLowRankMVN, AutoIAF) deferred to future milestone.
