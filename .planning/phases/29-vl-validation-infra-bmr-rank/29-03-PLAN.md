Add the two numerical-robustness guards that must exist BEFORE any recovery sweep or
SPM cross-validation: a C-order CSD round-trip regression test (VLREC-05) and a task
DCM precision-matrix intractability guard (VLROBUST-02).

Purpose: This project already shipped a C-order indexing bug in `csd_precision.py`
(fixed in commit 64e326f). The fix is correct but UNGUARDED — a future edit could
silently reintroduce the column-major<->row-major / complex-CSD transposition bug,
and it would only surface as asymmetric off-diagonal A errors much later in Phase 32.
A round-trip regression test locks the C-order contract in place before any SPM run
(pitfall S4 / VLREC-05). Separately, `TaskDCMForward.build_precision` returns a dense
`(T*N, T*N)` identity; at fine dt with long duration this is intractable
(dt=0.01, 100s, N=4 -> (4e4, 4e4)). The guard must fail LOUD with expected-vs-actual
matrix size (project rule: error messages include expected vs actual) and document
the dt >= 0.1 floor (pitfall N1 / VLROBUST-02).
Output: a guard in forward_models.py and two regression tests.
</objective>

  <name>Task 1: Add C-order CSD round-trip regression test</name>
  <files>tests/test_csd_corder_roundtrip.py</files>
  <action>
Create `tests/test_csd_corder_roundtrip.py`. Mark tests `@pytest.mark.vl`. Use
complex128 / float64. This guards the bug class fixed in commit 64e326f: the
PyTorch `.reshape(-1)` of an `(F, N, N)` tensor is C-order, so the linear index is
`w*N*N + i*N + j` with `j` varying FASTEST, then `i`, then `w`. (See the index block
in `csd_precision.py`: `j = idx % N; i = (idx // N) % N; w = idx // (N*N)`.)

Tests:
- `test_corder_index_roundtrip_recovers_asymmetric_elements`: build a deterministic
  ASYMMETRIC complex CSD of shape (F=3, N=3, N=3) where `csd[w, i, j] = (w+1)*100 +
  i*10 + j + 1j*(i - j)` (so `csd[w,i,j] != csd[w,j,i]` and the imaginary part is
  antisymmetric — exactly the structure that a transposition bug would corrupt).
  Flatten with `csd.reshape(-1)`. For every linear index `idx`, reconstruct
  `j = idx % N; i = (idx // N) % N; w = idx // (N*N)` and assert
  `flat[idx] == csd[w, i, j]` exactly (complex equality). This is the literal
  contract the precision builder depends on.
- `test_compute_csd_precision_block_structure_not_transposed`: import
  `compute_csd_precision` from `pyro_dcm.inference.csd_precision`. Pass the same
  asymmetric CSD. Assert it returns `(Q_list, nq)` with `nq == 1`, `len(Q_list) == 1`,
  and `Q_list[0].shape == (F*N*N, F*N*N)`. Then verify the diagonal of the precision
  block for frequency 0 corresponds to the (i,j) ordering implied by the C-order map:
  pick two distinct flat positions within frequency-0's block that map to
  `(i=0, j=1)` and `(i=1, j=0)` and assert the precision is finite and the two
  positions are NOT forced equal (i.e. the builder did not symmetrize away the
  asymmetry). The precise numeric value is not asserted — the GUARD is that an
  asymmetric input yields a layout where [0,1] and [1,0] land in distinct, correctly
  ordered slots. Add a comment citing commit 64e326f and pitfall S4.

Add `from __future__ import annotations`. Keep under 88 chars. Run ruff. This test
must NOT require a VL fit or cluster — it is pure tensor algebra, < 1s.
  </action>

`pytest tests/test_csd_corder_roundtrip.py -m vl -q` passes in < 2s.
`ruff check tests/test_csd_corder_roundtrip.py` clean.
  </verify>
  <done>
The round-trip test asserts the C-order `(j,i,w)` map recovers every element of an
