Add a new public function `rank_connections` to `bmr.py`. Signature:

    def rank_connections(
        posterior_mean: torch.Tensor,
        posterior_cov: torch.Tensor,
        prior_mean: torch.Tensor,
        prior_cov: torch.Tensor,
        prunable_indices: list[int],
        shrinkage_variance: float = 1e-8,
    ) -> dict:

Behavior — RELATIVE ranking, never absolute thresholding (this is the whole point;
see PITFALLS.md C1):
- For each index `k` in `prunable_indices`, build a single-connection reduced prior
  via the existing `make_reduced_prior_zero_connection(prior_mean, prior_cov, [k],
  shrinkage_variance)` and score it with the existing `bayesian_model_reduction(...)`.
  This is exactly K calls — do NOT call `enumerate_reduced_models` (that is 2^K).
- The single-prune `delta_f` is the "prune cost": MORE NEGATIVE delta_f => pruning
  that connection costs more evidence => the connection is MORE essential.
- Build a list of per-connection dicts: `{"index": k, "prune_delta_f": delta_f}`.
- Sort ascending by `prune_delta_f` (most-essential / most-negative first).
- Compute a separation-gap statistic. Because absolute delta_F values span orders of
  magnitude under Laplace overconfidence, define the gap on the SORTED prune costs as
  the largest consecutive drop in essentiality: iterate adjacent pairs in the sorted
  list and record `gap_after_rank[i] = prune_delta_f[i+1] - prune_delta_f[i]` (a
  positive number, since the list ascends). Report:
    * `ranked`: the sorted list (each entry gains `"rank"`: 1-based, and
      `"gap_to_next"`: the value above, or None for the last entry).
    * `separation_gap`: the maximum `gap_to_next` across the list.
    * `separation_after_rank`: the 1-based rank after which `separation_gap` occurs
      (i.e. the cut between essential and non-essential edges).
- Return `{"ranked": ranked, "separation_gap": float, "separation_after_rank": int,
  "prunable_indices": list(prunable_indices)}`.

Add a NumPy-style docstring citing [REF-070] Friston & Penny (2011) for the BMR
delta-F and explicitly documenting (in a Notes section) that absolute delta-F is NOT
used as a pass/fail criterion because VL Laplace overconfidence makes all reductions
deeply negative (cite cluster job 55772525); only relative ordering and the
separation gap are meaningful. Cast inputs to float64 (the underlying
`bayesian_model_reduction` already does, but document it). Add `rank_connections` to
the module `__all__`.

Error messages must include expected vs actual: if `prunable_indices` is empty,
raise `ValueError("rank_connections requires >=1 prunable index; got 0")`. If any
index is out of range for `posterior_mean.shape[0]`, raise ValueError naming the bad
index and the valid range. Keep functions <= 50 lines (factor a private helper if
needed). Run ruff + mypy.

Add a new public function `temper_vl_posterior` to `bmr.py`. Signature:

    def temper_vl_posterior(
        sigma_post: torch.Tensor,
        tempering_factor: float = 1.0,
    ) -> torch.Tensor:

Behavior (primitive only — calibration is Phase 31, do NOT calibrate here):
- Cast `sigma_post` to float64.
- Validate `tempering_factor > 0`; else raise
  `ValueError(f"tempering_factor must be > 0; got {tempering_factor}")`.
- Compute `sigma_tempered = tempering_factor * sigma_post`.
- Symmetrize: `sigma_tempered = 0.5 * (sigma_tempered + sigma_tempered.T)`.
- Assert positive-definiteness by attempting `torch.linalg.cholesky(sigma_tempered)`.
  On `torch.linalg.LinAlgError`, raise a `ValueError` (raise LOUD, do not warn-and-
  continue) whose message includes the matrix shape and the tempering_factor, e.g.
  `f"Tempered posterior covariance (shape {tuple(sigma_tempered.shape)}, "
  f"tempering_factor={tempering_factor}) is not positive-definite (Cholesky failed)."`
- Return `sigma_tempered`.

Document in the docstring (Notes): the motivation is that VL's ReML M-step
underestimates posterior covariance at high SNR; `tempering_factor > 1` inflates
covariance to partially restore an absolute-delta-F regime. State that the calibrated
factor is determined empirically in Phase 31 against the Phase 30 coverage curves, and
that default `1.0` is identity (backwards-compatible). Add `temper_vl_posterior` to
`__all__`. Run ruff + mypy.
  </action>
