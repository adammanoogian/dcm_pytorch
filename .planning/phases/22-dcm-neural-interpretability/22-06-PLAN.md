  <files>scripts/22_run_full_pipeline.py</files>
  <action>
1. Create `scripts/22_run_full_pipeline.py`:
   - argparse CLI: --camcan-dir (path to Cam-CAN data), --output-dir (root output),
     --n-subjects (int, default=50), --n-latent (int, default=6),
     --hidden-size (int, default=64), --submit-cluster (bool flag, if set submits sbatch
     instead of running locally), --skip-preprocess (bool flag, skip if already done),
     --skip-train (bool flag, skip if already trained)

   - Step 1 (if not --skip-preprocess):
     Run 22_preprocess_camcan.py with --data-dir camcan-dir --output-dir output-dir/preprocessed
     --n-subjects n_subjects

   - Step 2 (if not --skip-train):
     If --submit-cluster: submit 22_train_autoencoder.sbatch with env vars
     Else: run 22_train_autoencoder.py locally with --data-dir output-dir/preprocessed
     --output-dir output-dir/model --n-latent n_latent --hidden-size hidden_size

   - Step 3:
     Run 22_extract_latent_dynamics.py with --data-dir output-dir/preprocessed
     --checkpoint output-dir/model/best_model.pt --output-dir output-dir/latents
     --n-latent n_latent

   - Step 4:
     If --submit-cluster: submit 22_fit_dcm.sbatch with env vars
     Else: run 22_fit_spectral_dcm.py with --raw-csd output-dir/preprocessed/raw_csd_group.npz
     --latent-csd output-dir/latents/latent_csd_group.npz --output-dir output-dir/dcm_results

   - Step 5:
     Run 22_compare_connectivity.py with --raw-posterior output-dir/dcm_results/posterior_raw.npz
     --latent-posterior output-dir/dcm_results/posterior_latent.npz
     --output-dir output-dir/figures

   - Prints progress at each step. Handles errors gracefully (if a step fails, print
     the error and suggest rerunning with --skip flags).

   Use `from __future__ import annotations`, argparse, subprocess for calling other scripts.
   Follow the {stage}_{verb}_{noun}.py convention.

2. Submit the pipeline to M3 cluster:
   - First submit preprocessing (runs on CPU, moderate memory)
   - Then submit training (GPU node)
   - Then extraction + DCM fitting (CPU node)
   - Use sbatch --dependency=afterok:$JOBID for chaining

IMPORTANT: All heavy compute MUST route to M3 cluster. Do not run training or DCM
fitting on laptop. Only the orchestrator and comparison/plotting scripts run locally.

<task type="checkpoint:human-verify" gate="blocking">
  <what-built>
Complete Phase 22 pipeline: Cam-CAN MEG preprocessing, LSTM autoencoder training,

  </what-built>
  <how-to-verify>
1. Check training results:
   - Open output-dir/model/training_curves.json
   - Verify train loss decreased and val loss shows convergence (not diverging)
   - Reconstruction MSE should be "reasonable" (exact threshold TBD based on data scale)

2. Check latent dynamics:
   - Open output-dir/latents/latent_csd_group.npz
   - Verify shape is (64, N_latent, N_latent) complex
   - Latent CSD should show spectral structure (not flat noise)

3. Check DCM results:
   - Open output-dir/dcm_results/posterior_raw.npz and posterior_latent.npz
   - Verify posterior A matrices have reasonable values (not all zero, not exploding)
   - Check that ELBO decreased during fitting (convergence)

4. Review comparison figures:
   - Open output-dir/figures/
   - A matrix heatmaps: Do they show interpretable sensorimotor connectivity?
     Expected: strong precentral (motor) to postcentral (somatosensory) connections,
     some auditory-to-motor coupling (button press in response to tone)
   - Raw vs latent comparison: Does the latent representation produce cleaner or
     more structured connectivity than raw DCM?
   - Are the strongest connections neuroscientifically plausible?

5. Scientific assessment:
   - Does the latent DCM reveal connectivity structure that the raw DCM misses?
   - Or does the raw DCM already capture the relevant structure?
   - Are there spurious connections in either approach?
